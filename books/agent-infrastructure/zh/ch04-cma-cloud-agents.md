# 第四章 CMA：云端托管 Agent 与事件网关

让一位系统工程师在笔记本上开五个终端、维护本地 Git 工作树并挂起代理隧道，他得心应手；让一位花店店主、财务主管或社群运营照做，五分钟后他就会把电脑合上。

**`CMA`（`ChronoAI Managed Agent`，线上入口 `cma.nyxid.ai`，仓库 `ChronoAIProject/cma`）** 与事件网关 **`cmaeg`** 解决的正是「零运维云端上岗」。截至 **2026 年 11 月 27 日**，`CMA` 已恢复正式版本发布——**`v0.12.0`** 于 **2026 年 11 月 24 日**落盘（`main` 提交 `8f5ba69408`），`develop` 分支于 **2026 年 11 月 27 日**推进至 `c57da2e1e2`（PR `#4231`，已在 `v0.12.0` 之上再叠 `+722` 次提交）；同日公开仓库正式补齐 **`Apache-2.0` 开源许可**（`2026-11-24`，PR `#3647`）。

## 两大核心服务 + K8s 沙箱控制器撑起的四层云端底座

在运维部署拓扑上，`CMA` 刻意克制服务碎片化，将全部能力收敛为**两大核心应用服务（`cma-agent-manager`、`cma-event-gateway`）加 Kubernetes `agent-sandbox` 控制器**；从安全与控制流视角自下而上切开，则清晰呈现四层职责边界：

::: {.figure src="ch04-cma-four-layers"}
**`CMA`（`v0.12.0`，`Apache-2.0`，`cma.nyxid.ai`）四层云端托管架构。** 底层由 Kubernetes `agent-sandbox` 控制器与 `chrono-sandbox` 隔离沙箱承接，中上层收敛于 `cma-event-gateway`（`cmaeg`，覆盖 6 大 IM 平台 + `github`/`custom`）与 `cma-agent-manager`（托管运行时、约 `2.1 s` 凭证热重载与操作审计界面）；全程经 `NyxID` 零密钥代理对外通信。
:::

逐层拆解这四层与物理服务的对应关系：

1. **第一层：隔离沙箱执行与产物仓库（K8s `agent-sandbox` 控制器 + `chrono-sandbox`）**：每个托管智能体实例运行在独立隔离沙箱中，支持暂停、唤醒、生命周期管理、独立文件树、文档版本修订与受限只读分享链接，彻底隔绝跨租户文件系统与进程状态。
2. **第二层：多渠道事件网关 `cmaeg`（`cma-event-gateway`）**：把现实世界里形态各异的异步消息——**6 大 IM 平台（`telegram`、`lark`、`feishu`、`discord`、`slack`、`whatsapp`）外加 `github` 与 `custom` 自定义事件**——统一收口到分区事件线程，完成签名核验、重试去重、路由防抖以及发信前的两阶段预备／提交（`prepareoutboundmessage` / `commitoutboundmessage`），避免外部群聊里出现尴尬的重复刷屏或静默丢单。
3. **第三层：托管运行时与约 `2.1 s` 凭证热重载（`cma-agent-manager`）**：**（类比）** 传统云端代理把密钥焊死在容器启动环境变量里，增删一条服务权限就像为了拉一只断路器而炸掉整座变电站——正在跑的长任务当场中断。`CMA` 把凭证平面与沙箱进程解耦：一旦在 `NyxID` 里授权或紧急吊销某项服务，运行中的托管实例无需重启容器，在**约 `2.1 s`**（归档实测文档读数：空闲 `2.152 s` / 忙碌 `1.804 s`）内即可热收敛到新权限集——加权瞬间生效，止血瞬间断电。
4. **第四层：协作与审计工作面（`cma-agent-manager`）**：提供实时事件流、对话转录、沙箱文件树浏览、权限审批队列与用量报表，让业务负责人不必登服务器翻原始日志，就能看清智能体刚动过哪份文档、发过哪条外部消息。

## 诚实写明当前边界：今日仍聚焦单一主编码智能体运行时

**（立场）** 既然把 `v0.12.0` 与 `Apache-2.0` 许可亮在台前，就同样要把今天尚未跨越的边界原样写清，绝不拿路线图冒充现役（同步记录于[附录 B](appendix-b-security-and-readiness.md)）：

- 截至 **2026 年 11 月 27 日**，`CMA` `v0.12.0`（`Apache-2.0`）、两大核心应用服务加 K8s `agent-sandbox` 控制器、`cmaeg` 六大 IM 平台加 `github`/`custom` 路由以及约 `2.1 s` 凭证热重载均已上线服役；
- **但截至今日，云端托管实例仍然只开放单一主编码智能体运行时，尚未在云端公开面提供多异构智能体运行时的自由切换。**

如果一位重度构建者需要同时指挥几十个异构编码与研究智能体、直接操作本地多仓库 Git 工作树与真实浏览器，单靠云端单运行时远远不够——于是 ChronoAI 为他们造了整车的另一半驾驶舱：本地优先的多供应方空间编排画布 **`heca`**。第五章推开它的工作台。
