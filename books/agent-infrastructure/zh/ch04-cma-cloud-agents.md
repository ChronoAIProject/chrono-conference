# 第四章 CMA：云端托管 Agent 与事件网关

让一位系统工程师在自己的 MacBook 上开五个终端、装好依赖、配置好本地工作树，他甘之如饴；让一位花店店主、财务总监或社群运营去配本地环境，五分钟后他就会把电脑合上。

**`CMA`（`ChronoAI Managed Agent`，线上入口 `cma.nyxid.ai`）** 与配套事件网关 **`cmaeg`** 解决的就是「零运维云端上岗」：你不需要管容器编排、不需要管 Webhook 验签重放、不需要为了改一条服务权限而把正在干活的沙箱整台重启。

## 四层云端托管架构

把 `CMA` 的生产拓扑从下往上拆开，恰好是四层职责分明的云端底座：

::: {.figure src="ch04-cma-four-layers"}
**`CMA`（`cma.nyxid.ai`）四层云端托管架构。** 自下而上依次为：第一层隔离沙箱与产物存储（`chrono-sandbox`）、第二层多渠道事件网关与路由（`cmaeg`）、第三层托管智能体运行时与约 `2.1 s` 凭证热重载、第四层用户工作界面与受控分享链接；全程经 `NyxID` 零密钥代理对外通信。
:::

逐层看每一层的硬设计：

1. **第一层：隔离沙箱执行与产物仓库**：每个托管智能体实例运行在独立隔离沙箱中（配套 `chrono-sandbox` 暂停／唤醒／生命周期管理与独立文件树），支持文档版本修订、产物下载与受限只读分享链接，隔离跨租户文件系统与运行状态。
2. **第二层：事件网关 `cmaeg`**：把现实世界里五花八门的异步信号——GitHub Webhook、Lark/Feishu 原生事件、Telegram 更新、WhatsApp 回调与自定义事件——统一接进分区事件线程，负责签名核验、重试去重、防抖路由以及发信前的两阶段预备／提交（`prepareoutboundmessage` / `commitoutboundmessage`），大幅降低外部消息重复发送与静默漏发风险。
3. **第三层：托管运行时与约 `2.1 s` 凭证热重载**：传统云端代理一旦新增一项服务授权或吊销某个权限，往往要销毁重建整个容器、打断正在进行的长任务。`CMA` 把凭证平面与容器进程解耦：在 `NyxID` 调整服务绑定后，运行时在约 **2.1 秒**内热收敛到新权限集——既能即时加权，也能即时止血吊销。
4. **第四层：协作与审计界面**：提供实时事件流、对话转录、文件浏览、权限请求面板与用量报表，让管理员不用翻服务器日志就能一眼看清智能体刚动过哪些文件、发过哪条外联消息。

**云端热重载吊销（`hot-reload`）。** 演示 `CMA` 托管智能体在不中断沙箱进程的情况下，于约 `2.1 s` 热收敛窗口内即时同步 `NyxID` 权限变更与吊销状态，零明文密钥暴露。

## 诚实写明当前边界：今日仅开放单一主编码运行时

依照本书的诚实纪律，必须把 `CMA` 今天所处的真实边界写清（同步收录于[附录 B](appendix-b-security-and-readiness.md)）：

- 截至 2026 年 11 月 26 日，`CMA` 的四层托管架构、`cmaeg` 多渠道事件网关以及约 `2.1 s` 凭证热重载均已上线运行；
- **但当前云端托管实例仍聚焦于单一主编码运行时，尚未在公开面开放全部异构代理运行时的自由热切换。**

对于需要同时驾驶几十个异构编码与研究智能体、直接操作本地多仓库 Git 工作树与真实浏览器的重度构建者，ChronoAI 准备了整车的另一半驾驶舱——本地优先多供应方编排平台 **`heca`**。第五章推开它的控制台。
