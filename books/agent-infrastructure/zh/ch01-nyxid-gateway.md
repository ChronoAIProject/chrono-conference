# 第一章 NyxID：零密钥连接与身份底座

把公司的生产 API 密钥写进 `.env` 文件，然后直接交给一个能上网、能读外部网页、能收陌生人邮件的自主智能体——从安全工程的角度看，这相当于把保险柜密码印在信封背面，再派信使穿过一条满是扒手的街。

只要一页带毒的外部网页里藏着两行精心构造的间接提示注入，智能体就会老老实实地把环境变量里的每一把密钥打包发给攻击者。更荒唐的是，许多团队试图靠在系统提示词末尾多加一句大写加粗的「**严禁泄露任何密钥！**」来防卫。理查德·费曼在 1986 年《挑战者号事故总统委员会报告》附录 F 里留下的警句同样适用于安全工程：现实不会被公关欺骗，攻击者更不会因为你在提示词里用了感叹号就收手。

**`NyxID`** 的出发点冷酷而朴素：**不要指望智能体「自觉保守秘密」——从物理和网络拓扑上，让它压根摸不到任何明文秘密。**

## 四道硬边界：为什么明文密钥永远不进上下文

把 `NyxID` 的代理架构垂直切开，你能看到四道彼此隔离的安全层次：上方的智能体运行时只接触到一个窄作用域、短寿命、不透明的能力句柄；所有真正的 OAuth 令牌、服务密钥与刷新凭据全部封存在加密代理金库中，在请求离开边界发往上游服务的最后一刻注入，并在响应回传给智能体之前将一切敏感头字段洗净。

::: {.figure src="ch01-nyxid-proxy-layers"}
**`NyxID` 四层零密钥代理安全边界。** 智能体上下文始终保持零明文秘密，仅持受限能力句柄；所有调用必经策略关口，高危写操作另需人工审批，再由加密金库在代理内存完成 OAuth/API 令牌注入与响应清洗，统一对接 55 项内置服务、41 份 OpenAPI→MCP 规范、7 家 LLM 网关与 9 类消息渠道。
:::

用交互实验台 `NYXID//VAULT` 把「传统明文直连」和「`NyxID` 零密钥代理」放在同一场提示注入攻击下做一次正面撞击测试。先看 `direct-leak` 工况——当 $k$ 项外部服务的密钥直接躺在传统智能体的上下文或环境变量里，一次成功的外部网页提示注入，爆炸半径随服务数 $k$ 呈线性失控：

::: {.viz src="nyxid-credential-flow" preset="direct-leak" height="500"}
**传统明文注入泄露（`direct-leak`）。** 对比传统 `.env` 直连模式下，一条恶意外部响应如何在单轮内横向窃取全部挂载服务的明文凭据，暴露密钥数随连接服务数 $k$ 线性放大。
:::

现在把同一条带毒攻击切换进 `scoped-proxy` 工况：`NyxID` 代理在策略层核查当前令牌的作用域（例如仅允许 `read:issues`），拒绝越权外联，同时代理之外的模型上下文里根本不存在可供窃取的明文令牌，**爆炸半径恒定被压死在 `0`**。

::: {.viz src="nyxid-credential-flow" preset="scoped-proxy" height="500"}
**受限能力代理（`scoped-proxy`）。** 数据包经 `NyxID` 策略引擎按最小作用域校验，明文令牌只在加密代理内存内注入并剥离，上下文暴露密钥数严格为 `0`。
:::

## 透明账单：`1 credit = 1 USD` 与 BYOK 预算隔离

把 AI 员工放进真实公司时，紧随安全之后的第二个噩梦就是**账单失控**——一个陷入死循环的智能体完全可以在一个周末刷爆一张没有上限的企业信用卡。

`NyxID` 把计量与权限焊在了同一条代理管线上：基于 Lago 与 Stripe 的 Credits 计量遵循极其干净的换算（**`1 credit = 1 USD`**），同时原生支持企业自带密钥（BYOK）透传，并在每个智能体实例上执行硬性消费封顶。下面这张 `billing-meter` 实验卡演示了一次调用如何同时走过权限审计与预算扣减，到达封顶即硬熔断：

::: {.viz src="nyxid-credential-flow" preset="billing-meter" height="500"}
**Credits 与 BYOK 预算隔离（`billing-meter`）。** 实时追踪单次代理调用在 `1 credit = 1 USD` 计量模式与 BYOK 透传模式下的配额扣除、审计落账与单代理封顶熔断。
:::

把以上所有安全与计量机制合进一台完整的交互控制台——在下面的 `NYXID//VAULT` 实验室里，你可以自由调节挂载服务数量（`1` 至 `55` 项）、切换读／写／注入攻击／吊销四种工况，亲自验证为什么明文暴露曲线在 `NyxID` 这一侧永远紧贴零轴。（关于云端约 `2.1 s` 凭证热重载的 `hot-reload` 工况，我们将在第四章拆解 `CMA` 时专门展开。）

::: {.viz src="nyxid-credential-flow" height="560"}
**完整实验室：`NYXID//VAULT`。** 自由切换攻击与调用场景、拖动连接服务数（1–55），实时比较传统直连密钥爆炸半径与 `NyxID` 零密钥代理的零泄露不变量。
:::

当钥匙、身份与预算全部安全锁进 `NyxID` 之后，下一层要回答的问题是：**站在金库上面的智能体本身——也就是直接面向用户与团队的 `NyxBot`、`NyxAgent` 以及浏览器助手 SDK——如何分工协作、管理记忆并防止自我触发的无限递归？** 第二章见。
