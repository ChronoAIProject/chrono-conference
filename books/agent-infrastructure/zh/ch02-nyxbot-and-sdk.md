# 第二章 NyxBot、NyxAgent 与浏览器助手 SDK

把一位新手员工扔进办公室却既不告诉他管哪几张表、也不限制他一天能发几百封群发邮件，哪怕门禁卡再安全，他也能在一个下午把整间公司搅得鸡犬不宁。

`NyxID` 守住了钥匙和门禁，接下来必须解决**工作编排与防失控限额**。在 ChronoAI 的架构里，直接面向企业运营团队、发布会前厅与浏览器端用户的这一层，由 **`NyxBot`**、**`NyxAgent`** 以及轻量可嵌入的 **`nyx-assistant-sdk`** 共同构成。

## 为什么拆成「专项代理网格」而不是一只巨型聊天框

当你试图让单个上下文窗口同时记住公司财务准则、30 题媒体口径、1,108 个剧场座位状态以及 GitHub 仓库最新提交，上下文迅速膨胀变浊，指令互相打架，出错时你甚至分不清是哪一条规则把模型带偏了。

`NyxBot` 的解法像极了一间设计精良的机械变速箱：把职责拆成彼此边界清晰的**专项代理（Specialists）**，再通过明确写死在源码里的硬预算把规模、记忆与自动触发频率牢牢兜住。

下面这张结构图直接取自 `ChronoAIProject/NyxID@v0.78.0` 后端模型源码（`assistant_settings.rs`、`assistant_group.rs`、`assistant_agent.rs`，2026 年 11 月 3 日实测口径），没有一个数字是拍脑袋编的：

::: {.figure src="ch02-nyxbot-specialist-mesh"}
**`NyxBot` 专项代理网格与硬预算上限（`NyxID@v0.78.0` 实测常量）。** 中心调度器默认挂载 `8` 名专项代理（可扩至上限 `32` 名），单个协作群组上限 `8` 名代理；每名代理配备 `50` 条受控持久化记忆槽；自动化触发器严格受控于每小时 `30` 次、每日 `300` 次双重速率上限，彻底阻断事件风暴。

逐条审视这六个硬常量背后的工程克制（源码均位于 `ChronoAIProject/NyxID@v0.78.0` 的 `backend/src/models/` 目录）：

| 源码常量 | 精确数值 | 源码文件 | 解决什么真实风险 |
| --- | ---: | --- | --- |
| 默认专项代理数 | `8` | `assistant_settings.rs` | 开箱即可覆盖中小型团队标准分工，避免空配置焦虑 |
| 最大专项代理上限 | `32` | `assistant_settings.rs` | 支持中型组织横向扩展，同时限制路由复杂度失控 |
| 协作群组人数上限 | `8` | `assistant_group.rs` | 超过 8 个智能体在同群自由发言会急剧退化为回声噪音 |
| 单代理持久化记忆槽 | `50` | `assistant_agent.rs` | 强迫记忆提炼为高信噪比条目，拒绝无上限垃圾堆砌 |
| 触发器小时级上限 | `30 / hr` | `assistant_settings.rs` | 防止 Webhook 回路或消息重试瞬间打爆下游与账单 |
| 触发器日级上限 | `300 / day` | `assistant_settings.rs` | 为无人值守夜班设定可预期的最大动作预算 |

## 两条现役测试与运行场景：从演示财务账本到浏览器内嵌向导

这套网格并不是停留在配置结构体里的纸面参数，它已经在两条不同的现役场景中运行与演练：

1. **后端运营网格（`nyxbot-finance` 与 `nyxid-nyxbot-trials`）**：在 2026 年 11 月 25 日验收快照中，`NyxBot` 财务员在演示账本上跑通了 **24 / 28 项核心财务流程**（应收应付归类、异常票据提醒、账目核对），而 12-17 发布会前厅的礼宾 **Donna**（13/15）、花店 **小花**、社群运营（9/11，完成 75 次彩排动作）与社媒 **Auto-X**（11/13）全部共享这一套专项路由与触发限频机制。
2. **浏览器内嵌助手（`nyx-assistant-sdk`）**：你在 `https://live.trureturing.org/` 右下角以及 `street-corner` 虚拟前厅里看到的悬浮对话入口，背后正是同一套轻量浏览器 SDK。它无需把任何后端 API 密钥打包进前端 JavaScript——浏览器端只与 `NyxID` 会话端点握手，使任何网页应用（从科研观测站到外部商户官网）都能用极少接入代码挂上一位权限严格受限的现场向导。

## 从「会聊天」到「按规程办事」还差哪一块拼图？

看清了 `NyxBot` 的分工与限额后，一个老练的架构师马上会皱眉追问：**「如果每名专项代理的工作规程都只是手工填进后台表单的一段文字，那么当我们在 12-17 发布会打磨好一套礼宾或财务流程，怎么把它安全地打包、扫描、打版本号，再一键分发给下一百家商户？」**

答案正是整车架构的第二层核心——面向智能体的技能生命周期 API：**`Ornn` 与 `nyx-skills`**。第三章把它完整拆开。
