# 第五章 heca：本地优先的多供应方编排画布

如果你只跑一个智能体，一个终端窗口就够了。但当你像我们在第一卷第一章看到的那样——横跨 ChronoAI 与 The Omega Institute 共 74 个活跃仓库、六十天内落下 141,624 次提交，或者像筹备本次发布会这样同时推进四本书、二十六张图、七座交互实验台、四套演示文稿与五部短片——单窗口终端会在十分钟内变成一场灾难：

- 分支彼此踩踏，刚改完的测试被隔壁窗口覆盖；
- 权限弹窗淹没在十几个滚动的日志标签页里，没人知道谁在卡住等审批；
- 不同专长的代理运行在不同工具链与供应方上，互相看不见对方刚产出的截图、终端日志或任务进度。

**`heca`**（品牌名始终全小写，读作本地优先的「百手巨人」编排画布）正是为了终结这种多智能体混战而造的。

## 空间画布 + 隔离工作树：27 类智能体的统一指挥台

`heca` 的设计直觉非常朴素而务实：**把并发从看不见的后台进程搬到一张一目了然的空间画布上，同时用真实的 Git 工作树将并行改动的工作目录彼此隔离。**

::: {.figure src="ch05-heca-worktree-topology"}
**`heca` 本地优先空间画布与工作树隔离拓扑。** 单一本地画布空间统一调度 **27 类智能体**（`6` 类原生主供应方 + `21` 类 ACP 协议智能体，已迭代 `361` 个夜间构建）；每名工作代理获得独立 Git 工作树、专属终端与可视化浏览器面板，并经统一权限队列与目标账本（Goal Ledger）受控协作。
:::

把这张图拆成四个日常高频救命的工程原语：

1. **真正的多供应方开放架构（`6 + 21 = 27`）**：`heca` 不把你绑死在任何一家单一上游供应商上。截至 2026 年 11 月 26 日，它原生接入 **6 类主代理供应方**，并通过开放的 Agent Client Protocol 兼容 **21 类 ACP 智能体**，合计 **27 类**可混编执行体——你可以按任务性质自由指派不同专长的执行器，让它们在同一个团队画布里接力协作。
2. **一任务一工作树（Git Worktree Isolation）**：每当编排者派发一项并行改动，`heca` 自动管理独立 Git 工作树与专属终端，不复制整个 `.git` 对象库即可各自隔离工作目录与构建产物；完成后再干净归档或合并。
3. **内置共享浏览器与视觉回路**：每个工作空间直接挂载可控浏览器面板（导航、读 DOM、截屏、执行前端验收），让前端可视化与排版校验不必离开编排画布。
4. **集中权限队列与目标账本（Goal Ledger）**：所有子代理抛出的越权申请统一汇总进权限队列，由人类或有授权的编排者审慎放行或拒绝；长周期目标（如连续多小时的迭代构建任务）则把轮次、消耗与真实证据记入目标账本，绝不靠口头声称「差不多完成了」。

## 三百六十一个夜间构建，与一条绝不遮掩的现状声明

从 2026 年 9 月至 11 月的 60 天内，`heca` 仓库线累计记录了 **12,053 次提交**（近 30 天 **4,404 次**），已连续产出 **361 个夜间构建**，每天直接驱动 ChronoAI 内部的高密度软件工程与多卷出版生产——你此刻正在读的这套发布会四卷书的并行生产本身，就运行在 `heca` 的网关与编排原语之上。

但正如我们在第一卷第二章立下的军令状：**尚未公开发布的源码，绝不提前冒充开源。** 截至 2026 年 11 月 26 日，**`heca` 的源码尚未对外公开**（组织 `getheca` 下的公共发布包与文档正在整理阶段）。我们在[附录 B](appendix-b-security-and-readiness.md) 里把这一点以明文标注为 `源码待公开`，绝不让外部开发者白跑一趟 404 链接。

好了——现在云端有 `CMA`，本地有 `heca`，几十个智能体能以惊人速度同时写代码、画图、建页面。可速度越快，悬在头顶的那把剑就越锋利：**怎么防止这群高速运转的智能体在合并前偷偷跳过测试、修改判分脚本、或者为一次纯文字修改把全仓浏览器测试盲目重跑两小时？**

答案就在整车的第四层——也是全公司最冷酷无情的守门员：**`chrono-harness` 与 `sshx`**。第六章直入核心。
