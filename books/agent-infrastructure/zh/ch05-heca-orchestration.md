# 第五章 heca：本地优先的多供应方编排画布

只跑一个编码智能体，一扇终端窗口足够了。可一旦你面对的是 ChronoAI 与独立科研品牌 The Omega Institute 在 60 天窗口内（`2026-09-20` 至 `2026-11-19`）横跨 74 个活跃仓库落下 141,624 次提交的并发密度，或者像筹备本次发布会这样同时推进四卷双语专著、静态图、交互实验台、演示文稿与视频，普通终端标签页会在十分钟内溃散成一团乱麻：

- 并行写入彼此践踏，刚跑通的测试被隔壁窗口静默覆盖；
- 权限弹窗埋在十几个狂滚日志的标签页深处，没人知道哪只代理已经卡死等审批；
- 不同供应方的专项执行体彼此失明，看不见对方刚拍下的浏览器截图、终端输出与目标进度。

**`heca`**（品牌名始终全小写，意为本地优先的「百手巨人」空间编排画布）造出来就是为了把这种多智能体混战从物理层掐断。

## 带独立台钳的机工工作台：27 类智能体的统一指挥面

**（类比）** 让十名焊工挤在一张工作台上同时切割、焊接同一块钢板，还不准他们互相打招呼，结局绝不会是十倍效率，只会是一堆废铁。`heca` 造的是**一整排各自锁死独立台钳的机工工作台**：把并发从看不见的后台进程搬到一张全局可视的空间画布上，再用真实的 Git 工作树给每一项并行任务夹上独立台钳，绝不让两把焊枪同时碰同一份工作目录。

::: {.figure src="ch05-heca-worktree-topology"}
**`heca` 本地优先空间画布与工作树隔离拓扑。** 单一本地画布空间统一调度 **27 类智能体**（`6` 类原生主供应方 + `21` 类 ACP 协议智能体，累计 **`360` 个夜间构建**、最新 `0.1.0-nightly-20261121-1`）；每名工作代理获得独立 Git 工作树、专属终端与可视化浏览器面板，覆盖 6 平台与 4 种可用运行时，并经统一权限队列与目标账本（Goal Ledger）受控协作。
:::

日常高密度工程里真正救命的是这四项硬原语：

1. **真正的多供应方开放接入（`6 + 21 = 27`）**：`heca` 拒绝把构建者锁死在任何一家单一上游供应商里。截至 **2026 年 11 月 27 日**（`main` 提交 `5111cd3b1f`，PR `#2870`），它原生集成 **6 类主代理供应方**，并通过开放的 Agent Client Protocol 接入 **21 类 ACP 智能体**，合计 **27 类**可混编执行体——在同一块空间画布里按任务所长指派、接力、互相验收。
2. **一任务一工作树（Git Worktree Isolation）**：派发并行改动时，`heca` 自动挂载共享底层 `.git` 对象库但工作目录彼此隔离的独立 Git 工作树与专属终端，不重复拷贝大仓库就能把构建产物、暂存区与脏改动彻底分开，收工后干净合并或归档。
3. **跨平台画布与内嵌浏览器视觉回路**：覆盖 **6 大平台**（macOS / Linux / Windows 桌面端、iOS / Android 移动端与 Web），每个工作空间直接内嵌可控浏览器面板（导航、读 DOM、截屏、页面脚本评估），让可视化与排版核验不必跳出编排器。
4. **集中权限队列与目标账本（Goal Ledger）**：所有子代理抛出的越权动作全部汇入单一可检视的权限队列，由人类或获授权编排者逐项放行或拒绝；长周期自主任务把轮次、消耗、活跃时长与真实产物回执记入目标账本，绝不采信口头一句「差不多做完了」。

## 三百六十个夜间构建，以及两条绝不回避的硬边界

在截至 2026 年 11 月 19 日的 60 天统计窗口内，`heca` 工程线累计记录 **12,053 次提交**（近 30 天 **4,404 次**）；截至 **2026 年 11 月 27 日**，已精确产出 **`360` 个夜间构建标签**（最新标签 **`0.1.0-nightly-20261121-1`**），`main` 已推进至 `5111cd3b1f`（PR `#2870`）。此刻你正在读的这套四卷发布会专著，本身的并行写作与编排就运行在 `heca` 网关之上。

**（立场）** 拿音叉敲敲自己的招牌：吹嘘 `360` 个夜间构建和 `27` 类代理很容易，真正见骨气的是把**今天仍未打通、仍未公开的两道边界原样摆在第一页**（同步收录于[附录 B](appendix-b-security-and-readiness.md)）：

- **四条可用运行时，一条仍受阻**：今日实际可用的本地隔离运行时为 **`Host`、`macOS Sandbox`、`Docker`、`Podman` 共 4 种**；**Apple `container` 运行时仍处于受阻状态**，不凑成「五种全通」去糊弄读者。
- **`getheca/heca` 源码目前仍为内部私有**：尽管 `getheca` 组织已公开分发构建产物与站点文档，但核心源码仓库至今尚未对外开源。把私有仓库提前吹成「开源产品」是最廉价的自欺；我们在全书每一处表格里都把这一点钉死为 **`私有／源码未公开`**，绝不让任何外部工程师兴冲冲点开链接撞上一堵 404 墙。

云端 `CMA` 与本地 `heca` 把执行速度推上了前所未有的量级。可速度越快，没刹车的车祸就越惨烈：**怎么防止这群每秒写出几十行代码的智能体在合入前偷偷跳过测试、篡改判分脚本，或者因为改了三个错别字就把两小时全仓浏览器测试盲目重跑一遍？**

答案就在整车的第四层——全公司最冷血、最不讲情面的机械裁判：**`chrono-harness` 与 `sshx`**。第六章把刹车钳拆开看个明白。
