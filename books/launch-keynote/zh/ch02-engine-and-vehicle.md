# 第二章 发动机人人可买，我们造的是整车

如果你走进一间赛车维修间，把一台五百马力的裸发动机放在水泥地上直接拧油门，你不会得到一圈赛道成绩——你会得到一阵震耳欲聋的尖叫、满屋子滚烫的机油，以及一个随时会把地板掀翻的铁疙瘩。

今天大多数人谈论「AI 落地」，其实正蹲在水泥地上盯着一台裸发动机发愁。

过去两年，全世界最顶尖的实验室把几乎全部算力都押在了把发动机越造越强上。结果很美妙，也很残酷：**强发动机成了人人按次付费就能租到的公开商品。** 你可以花几美分买到一流的推理马力，你的竞争对手也能在三分钟内买到一模一样的一台。真正决定你能不能把车开上真实公路、载着真实客户平安到站的，从来不是把裸发动机绑在滑板上，而是**底盘、油路、方向盘、刹车与安全带**——也就是一整辆能换发动机却不停转的**整车**。

::: {.remark #rem-ch02-vehicle-analogy title="结构类比：发动机与整车"}
「裸发动机 vs. 整车」是描述推理模型与智能体基础设施分工的工程类比，用来说明为何密钥隔离、技能治理、运行时编排与可执行判官决定生产可用性；它不是数学定理。
:::

## 裸发动机为什么上不了真实公路

把「裸接模型」和「整车基础设施」并排放在同一张工程剖面图上，差别立刻清晰得不需要一句废话。左边的裸发动机把明文 API 密钥直接塞进环境变量，把业务流程写成一段随时会漂移的长提示词，没有任何写操作刹车，一旦外部网页藏进一句提示注入，整辆车连带着你的钱包一起冲下悬崖。右边的整车把发动机装进可插拔的机舱，让所有危险的现实世界接触都经过五层冷冰冰的硬边界。

::: {.figure src="ch02-engine-vs-vehicle"}
**裸发动机与五层整车剖面对比。** 左栏为无护栏的裸接智能体（明文密钥暴露在上下文、提示词漂移、无审计回滚）；右栏为 ChronoAI 五层整车架构，推理引擎可随时热替换，所有凭证、技能、沙箱与判官约束由底盘统一承载。
:::

这五层底盘并不是凭空画在白板上的愿望清单，而是已经在 ChronoAI 仓库群里每周承受数千次提交与真实请求的在役系统。把它们从底层到前台逐一拆开，就像拆解一台机械表：

1. **第一层：身份与零密钥底座（`NyxID` `v0.78.0`）**
   这是整辆车的点火锁与防爆油箱。`NyxID` 内置 **55 项服务**、**41 份 OpenAPI→MCP 规范**、**7 家 LLM 网关路由**与 **9 类消息渠道适配器**，现已开放公开注册（`invite_code_required: false`），并提供透明的 Credits 计量（`1 credit = 1 USD`）与 BYOK 透传。核心铁律只有一条：**明文密钥永远留在加密代理金库内，绝不进入智能体上下文。**
2. **第二层：技能生命周期 API（`Ornn` `v0.18.0` 与 `nyx-skills`）**
   把智能体的工作流当成真正的软件而不是聊天咒语。`Ornn` 提供 **134 个 OpenAPI 操作端点**（覆盖 109 条路径）、**18.7 万行源码**与 **286 份测试文件**，配合公共技能库 `nyx-skills` 里的 **163 项技能**（164 个插件条目），把每一项技能都纳入版本冻结、AgentSeal 安全扫描与权限绑定。
3. **第三层：云端托管与本地编排双引擎（`CMA` 与 `heca`）**
   不同任务需要不同的驾驶舱。云端托管智能体 **CMA**（`cma.nyxid.ai`）采用四层架构与独立事件网关（`cmaeg`），支持约 **2.1 秒**的凭证热重载，让团队与商户免运维直接上岗；本地优先编排平台 **heca** 则面向深度开发者，在画布空间里统一调度 **27 类智能体**（6 类原生主供应方 + 21 类 ACP 协议智能体，已迭代 361 个夜间构建），为每位智能体分配隔离的 Git 工作树、终端与浏览器面板。
4. **第四层：可执行判官与协作治理（`chrono-harness` `v0.1.4` 与 `sshx`）**
   不要指望用礼貌的提示词求智能体「请务必仔细测试」。`chrono-harness`（**27.2 万行 Rust**，横跨 **25 个模块化仓库**，面向 Linux x86_64 与 macOS aarch64 各发布 **16 个**预编译二进制工具）把规则写进声明式 `FILEMAP` 与 `DELTA` 增量选择判官：只测改动真正触及的依赖边，漏登直接报错而非盲猜。`sshx`（`v1.0.0-beta.58`）则把多视角独立评审接进研发主线。
5. **第五层：真实业务与科研表面（`chrono-metaverse`、`chrono-cd`、`Living with AI`、`trureturing`）**
   整车造好不是为了摆在展厅吃灰。它直接承载 12-17 线上发布会的 `street-corner` 三维虚拟会场、零运维部署底座 `chrono-cd`、通向物理家庭设备的 `Living with AI`（`nyx-homeassistant-node v1.1.1-alpha.52`），以及全天候在 Lean 4 内核上挖掘数学真理的 `trureturing`。

## 亲手验证：四个决定整车生死的关键工况

与其听我们在纸上吹嘘底盘有多稳，不如直接坐进驾驶座，用下面的交互示意实验台 `VEHICLE//STACK` 亲自演练四个最容易把普通 AI 原型当场撞散的典型工况。

第一个工况叫**热换发动机**。假设你的工作流已经跑到一半，上游突然换代或出现配额拥堵，你把机舱里的通用推理核从 `Engine Alpha` 瞬间切换成 `Engine Beta` 或本地核心。在散装脚本里，换引擎往往意味着重写提示、重登凭证、丢失会话状态；在整车架构里，由于身份、技能、审批与判官全部沉淀在底盘，换完引擎后整条任务流不中断、不重新鉴权、零状态丢失。

::: {.viz src="engine-vehicle-stack" preset="swap" height="500"}
**热换发动机（`swap`）。** 机舱在任务执行中段将推理核由 `Engine Alpha` 热切换至 `Engine Beta`；下方青色底盘总线（`NyxID`、`Ornn`、`CMA / heca`、`chrono-harness`）保持连续贯通，上下文泄露密钥数始终为 `0`。
:::

第二个工况叫**零明文金库**。把注意力盯紧 `NyxID` 那一道分界线：当智能体发出一次调用请求，穿过模型机舱的只有一个受窄作用域限制的不透明能力句柄（Scoped Capability Handle）。真正的 OAuth 令牌与 API 密钥只在代理层内存中注入，并在响应回传给智能体前彻底剥离。哪怕外部返回了一段恶意提示注入，机舱里也没有任何明文钥匙可供偷走。

::: {.viz src="engine-vehicle-stack" preset="vault" height="500"}
**凭证不进上下文（`vault`）。** 数据包跨越 `NyxID` 边界时，模型侧仅可见窄作用域能力句柄，明文密钥在金库内完成注入与清洗，`plaintext_in_context` 恒定保持 `0`。
:::

第三个工况是区分**玩具**与**员工**的分水岭：**写操作人工闸门**。查一份财报、读一个仓库、核对一条座位余量，可以放心让智能体全天候自动执行；但只要数据包触及真正会改变现实世界的写操作——划转资金、对外发送未审核新闻稿、删除生产资源——系统会在琥珀色闸门前硬性暂停，直到人类给出明确签批才放行。

::: {.viz src="engine-vehicle-stack" preset="approval" height="500"}
**写操作人工闸门（`approval`）。** 只读查询沿青色通道自动放行；涉及外部状态变更的写请求在琥珀色人工审批闸门前挂起等待授权，确保不越权执行。
:::

第四个工况最能暴露架构的诚实度：**一键紧急吊销**。当某个云端托管会话出现异常，管理员在 `NyxID` 撤回授权；运行在 `CMA` 云端沙箱中的代理无需重启容器，也不需要轮换全部上游厂商主密钥，在 `CMA` 报告约 **2.1 秒**的热重载收敛窗口内即可刷新凭证态，实验卡中演示下游调用随即被拦截为 `403 REVOKED`，快速止血。

::: {.viz src="engine-vehicle-stack" preset="revoke" height="500"}
**一键热吊销（`revoke`）。** 演示在 `NyxID` 撤回会话授权后，`CMA` 云端运行时在约 2.1 秒热重载窗口内完成权限收敛、示意调用转为 `403 REVOKED` 拦截状态，无需重启运行中沙箱。
:::

## 把未完成的螺丝也摊在台面上

整车主义绝不等于完美主义。如果我们在发布会上把半成品包装成「全宇宙终极完全体」，那和我们在第一章嘲笑的淘金热没有任何区别。把今天的真实边界写死在这里（完整矩阵见第二卷《整车工程》附录 B）：

- **`heca` 源码尚未公开**：它已经在内部连续产出 361 个夜间构建、支撑高密度多代理日常提交，但对外开源整理仍在进行中，我们不提前声称它已公开源码。
- **`CMA` 当前聚焦单一主编码运行时**：云端四层托管架构与约 `2.1 s` 热凭证重载已经上线运行，但多运行时全面铺开仍在演进队列里。
- **`chrono-harness` 规范仍标注 `completeness_proven: false`**：16 个二进制工具和 `FILEMAP` 增量判官已在日常仓内强制服役，但规范文档诚实记录其形式完备性尚未被穷尽证明。

把以上四个工况合在一处，下面这台完整的交互示意实验室 `VEHICLE//STACK` 允许你自由组合引擎插槽、审批策略与紧急吊销开关，直观检验整条数据总线在各类组合下的零密钥设计不变量。

::: {.viz src="engine-vehicle-stack" height="560"}
**完整交互示意实验室：`VEHICLE//STACK`。** 自由切换机舱推理引擎、读写审批策略与吊销开关，沿时间轴追踪示意工具调用穿过五层整车架构的生命周期与零密钥不变量。
:::

造出一辆能跑的整车只是起点。当一个组织里同时跑着几十个智能体、上百项技能、数十个服务与数百个仓库，如果每辆车各修各的路，协作很快就会重新陷入碎片化泥潭。下一章我们往高处再升一层：为什么 ChronoAI 坚持把整套生态织成「一张网」，以及如何用可复利的基础设施去驯服技术演进里的「红皇后赛跑」。
